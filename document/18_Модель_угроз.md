# 🎭 Модель угроз (Threat Model)

> Создан по итогам аудита: у каждого атакующего — своя модель.
> Формат: актив → угроза → вероятность → ущерб → митигация → остаточный риск.

---

## 1. Атакующие и их цели

| #   | Кто                          | Чего хочет                                         |
| --- | ---------------------------- | -------------------------------------------------- |
| A   | Злой покупатель              | получить скрипт без оплаты / поделиться с друзьями |
| B   | Злой продавец                | получить деньги за мусор, обмануть покупателя      |
| C   | Владелец взломанного сервера | украсть все лицензии, находящиеся на сервере       |
| D   | Вор license key              | угнать аккаунт и лицензии жертвы                   |
| E   | Атакующий в сети             | replay/MITM/подмена License Server                 |
| F   | Пират                        | слить скрипт в паблик                              |
| G   | Компрометация площадки       | взломанный админ / БД / S3 / CI                    |

## 2. Разбор по сценариям

### A. Злой покупатель

```
актив: зашифрованный blob
угроза: копирует файл и раздаёт друзьям
вероятность: высокая
ущерб: потерянные продажи
митигация: blob без DEK не расшифровать; DEK привязан к installation
остаточный риск: если скопирован вместе с installation secret — см. F
```

### B. Злой продавец

```
актив: деньги покупателей, доверие площадки
угроза: продаёт мусор/малварь, исчезает после продажи
вероятность: высокая (реальность MTA-рынка!)
ущерб: репутация площадки, возвраты
митигация: escrow (Safe Deal), moderation flow, отзывы только после
  покупки, disputes, аудит загрузок (запрет на admin-ACL/external
  downloaders/obfuscated Lua без disclosure)
остаточный риск: мусор проходит модерацию — ловится отзывами+disputes
```

### C. Взломанный сервер покупателя

```
актив: installation secret, расшифрованные скрипты
угроза: дампит все лицензии, переносит на другой сервер
вероятность: средняя
ущерб: потерянные продажи
митигация: 1 installation = 1 лицензия; уведомление при
  переустановки MTA/смене environment; challenge при аномалиях
остаточный риск: MEMORY DUMP НЕВОЗМОЖНО ПОЛНОСТЬЮ ПРЕДОТВРАТИТЬ —
  честно признаём: DRM = cost-raising (см. 09, раздел 0)
```

### D. Угон аккаунта

```
актив: аккаунт с лицензиями
угроза: крадут license key (phishing, слив)
вероятность: средняя
ущерб: потеря доступа покупателя
митигация: 2FA (обязательно для продавцов), rate limit, аномалии
  входа, sessions/logout all
остаточный риск: фишинг неустраним — компенсируется support'ом
```

### E. Атакующий в сети

```
угроза: replay lease, подмена DNS, фейковый License Server, MITM
вероятность: низкая-средняя
ущерб:绕过 лицензии
митигация: Ed25519 подпись (ключ зашит в модуль), nonce+TTL,
  TLS поверх HTTP-payload
остаточный риск: обновление подписанного payload требует ключа —
  вероятностно безопасно до компрометации ключа
```

### F. Пират (массовый слив)

```
актив: скрипты после расшифровки
угроза: декомпилирует, переименовывает, перепаковывает, сливает
вероятность: высокая, если есть спрос
ущерб: потерянные продажи
митигация: watermark + forensic scoring (confidence 97% — это
  вероятность, не вердикт), мгновенный lease-revoke при нахождении
остаточный риск: часть fingerprint уничтожается при перепаковке
```

### G. Компрометация площадки

```
угроза:
  G1: compromised admin — важно: RBAC, admin не делает refund единолично
  G2. compromised database — license leak, financial data leak
  G3. compromised object storage (S3) — воровство blob'ов
  G4. compromised CI — малварь в билдах
  G5. потеря signing keys — критично, хуже потери БД
митигация:
  G1: roles + permissions, обязательное 2FA, audit_log всех действий
  G2: encryption at rest, дампы зашифрованы, запрет внешнего доступа
  G3: временные signed URL, минимальный доступ, checksum в БД
  G4: pinned runners, scanning билдов
  G5: ключи НЕ в БД, отдельное хранение, план ротации, key_id в токенах
остаточный риск: полный институт защиты не заменит маленькая площадка
  сразу — компенсируется планом на случай инцидентов (10, раздел 7)
```

## 3. Ключевой вывод

Атаки C и F объединяет одно: **plaintext неизбежно появляется на
машине покупателя**. Мы НЕ обещаем «защиту от копирования вообще» — мы
обещаем:

1. Массовое копирование существенно усложнено.
2. Каждая копия атрибутируется (forensic confidence).
3. Утечка локализуется за ≤24ч (lease-revoke).

Это честная позиция, и она же — рыночная норма для DRM.
