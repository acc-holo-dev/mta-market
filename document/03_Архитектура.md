# 📐 Архитектура проекта (Структура папок и файлов)

> Этот документ описывает, КАК физически устроен проект:
> где лежит код, какие папки за что отвечают, что запускается.

---

## 1. Общая структура (монорепозиторий)

Проект живёт в одном репозитории — все части в одном месте, что
удобно для разработки силами одного человека.

```
mta-market/
│
├── apps/
│   ├── web/                      # FRONTEND (React + TypeScript)
│   │   ├── src/
│   │   │   ├── components/       # Переиспользуемые компоненты (кнопки, карточки)
│   │   │   ├── pages/            # Страницы сайта
│   │   │   ├── api/               # Запросы к Backend
│   │   │   ├── hooks/            # React Query хуки
│   │   │   └── App.tsx           # Точка входа
│   │   └── package.json
│   │
│   └── server/                   # BACKEND (Node.js + TypeScript)
│   │   ├── src/
│   │   │   ├── modules/          # Модули системы (см. раздел 3)
│   │   │   ├── jobs/              # Фоновые задачи (cron, очереди)
│   │   │   ├── lib/               # Вспомогательные библиотеки (крипто, JWT)
│   │   │   ├── db/                # Схема БД и миграции
│   │   │   └── index.ts           # Точка входа
│   │   └── package.json
│
├── packages/
│   ├── shared/                   # Общие типы Frontend ↔ Backend
│   │   └── types/                # TypeScript-интерфейсы, validation-схемы
│   │
│   └── drm-module/               # DRM-МОДУЛЬ (C++, отдельная сборка)
│       ├── source/
│       │   ├── license/          # Проверка лицензии, heartbeat
│       │   ├── crypto/            # Расшифровка скриптов
│       │   └── hwid/              # Сбор HWID
│       └── build.sh               # Скрипт сборки
│
├── infra/                        # ИНФРАСТРУКТУРА
│   ├── docker-compose.yml        # PostgreSQL + Redis + MinIO одной командой
│   ├── nginx/                    # Конфиг reverse-proxy
│   └── scripts/                  # deploy.sh, backup.sh, migrate.sh
│
├── document/                     # ЭТА ПАПКА — вся документация
├── .env.example                  # Шаблон переменных окружения
└── README.md                     # Краткая инструкция «с чего начать»
```

---

## 2. Обоснование структуры (почему так)

| Решение                | Почему                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| `apps/` + `packages/`  | Backend и Frontend разделяем, но живут рядом — общий TypeScript-типы экономят время            |
| `packages/shared/`     | Если API меняет поле — Frontend узнает об ошибке сразу при сборке, а не в продакшене           |
| `packages/drm-module/` | C++ не совместим с Node.js стеком, но живёт в том же репо, чтобы нельзя было «забыть» про него |
| `infra/`               | Всё, что связано с сервером, хранится вместе с проектом, а не «у меня где-то был скрипт»       |
| `db/` внутри backend   | Миграции БД — часть backend, версионировать их нужно вместе с кодом                            |

## 3. Модули Backend (папка `modules/`)

Каждый модуль — самодостаточный «блок» с одним ответственностью:

```
modules/
├── auth/          # Регистрация, вход, JWT-токены, сброс пароля
├── users/         # Профили, роли (покупатель/продавец/админ)
├── catalog/       # Каталог, поиск, категории, фильтрация
├── resources/      # CRUD ресурсов (загрузка скриптов продавцом)
├── licenses/       # ⭐ ЯДРО: выдача, HWID, продление, отзыв
├── payments/      # Платежи, подписки, escrow-балансы
├── reviews/       # Отзывы, рейтинги
├── orders/        # Биржа заказов (пока не реализовано)
├── chat/          # WebSocket-чат
├── notifications/ # Email + in-app уведомления
└── admin/         # Админ-панель API
```

**Правило одного направления:** модули могут вызывать друг друга
только через публичные функции модуля. Никакого «импортируем что хотим
и откуда хотим».

## 5. Инфраструктура (что и где крутится)

```
                    Cloudflare (DNS, защита от DDoS)
                          │
                    ┌─────▼──────┐
                    │  Nginx     │  SSL-сертификат, раздача статики
                    │  (80, 443) │
                    └─────┬──────┘
              ┌───────────┼──────────────┐
        ┌─────▼────┐  ┌───▼─────┐  ┌────▼─────┐
        │ Frontend │  │ Backend │  │ WebSocket│
        │ (статика)│  │ (API)   │  │  (чат)   │
        └──────────┘  └───┬─────┘  └──────────┘
                          │
        ┌────────┬────────┼────────┬─────────┐
  ┌─────▼────┐ ┌───▼─────┐ ┌──▼──────┐ ┌───▼──────┐
  │PostgreSQL│ │  Redis  │ │  MinIO  │ │  Аренда  │
  │   (БД)   │ │ (кэш)  │ │  (файлы)│ │  VDS     │
  └──────────┘ └────────┘ └─────────┘ └──────────┘
```

Всё это разворачивается одной командой `docker-compose up -d`
(см. `05_Для_человека.md`).
