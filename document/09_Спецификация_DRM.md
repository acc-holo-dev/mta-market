# 🛡️ Спецификация DRM — защита скриптов

> Сердце площадки: как скрипты шифруются, продаются, защищаются.
> Документ описывает протокол взаимодействия DRM-модуля (C++) с License Server.

---

## 1. Участники

| Компонент | Язык | Где живёт | Роль |
|---|---|---|---|
| DRM-модуль | C++ (на базе mta-sdk-module) | MTA-сервер покупателя | Расшифровывает, проверяет, отключает |
| License Server | часть Backend | VDS площадки | Подписывает лицензии, отзывает |
| Build Tool | Node.js CLI | машина разработчика | Шифрует и упаковывает скрипты продавца |

## 2. Криптографические примитивы

| Задача | Алгоритм | Ключ |
|---|---|---|
| Подпись токена лицензии | Ed25519 (libsodium) | приватный: только на License Server; публичный: зашит в модуль |
| Шифрование скрипта | AES-256-GCM | DEK (Data Encryption Key) |
| Обёртка DEK | AES-256-GCM | ключ из `HKDF(license_key_id + hwid_hash)` |
| Anti-replay | nonce (16 байт) + timestamp + TTL | — |

## 3. Жизненный цикл скрипта

### 3.1 Продавец публикует
```
1. Upload → Backend проверяет ресурс (валидация zip, smoke-тест)
2. Build Tool Backend'а:
   a. luac_bytecode = компиляция Lua
   b. DEK = random 32 bytes
   c. blob = AES-GCM(bytecode, DEK)       → сохраняем на S3
   d. wrap = AES-GCM(DEK, server_secret)  → в таблицу (не в blob!)
```

### 3.2 Покупатель активирует
```
1. DRM-модуль (C++) при первом запуске собирает HWID:
   hash(MAC + volume_serial + CPU_id)
2. POST /v1/activate { license_key, hwid, nonce }
3. License Server:
   - проверяет: лицензия активна? HWID-слот свободен? не превысил лимит?
   - YES: привязывает HWID, отвечает подписанным токеном
4. Модуль проверяет Ed25519-подпись публичным ключом (зашит в .dll)

Пока лицензия не активирована, decrypt(blob) невозможен:
нет DEK → нет расшифровки → скрипт не работает.
```

### 3.3 Heartbeat (каждые 30 минут)
```
POST /v1/verify { license_key_id, hwid, nonce, resource }
→ { status: active, deks: {wrapped_DEK}, sig }
```
- License Server может ответить `revoked` / `expired` → модуль отключает скрипт.
- Сервер недоступен → модуль работает по локальному кэшу **48 часов (grace)**,
  потом останавливается.
- Отвечённый `wrapped_DEK` можно расшифровать только зная правильный HWID:
  украденный ответ не работает на другой машине.

### 3.4 Обновление скрипта
```
1. Продавец заливает новую версию
2. Покупатель жмёт "Обновить" в кабинете
3. Модуль скачивает новый blob, старый занижается
4. Изменения лицензии не требуют: ресурс_id остался прежним
```

## 4. Что модуль делает в C++ (и что НЕ попадает в Lua)

**Модуль НЕ отдаёт в Lua:**
- ключи (DEK, KDF) — никогда не покидают C++
- функцию расшифровки — только результат (`decrypt → load → execute`)

**Модуль отдаёт в Lua:**
- `license_check(resource_name) → boolean` — безопасно: Lua-код лишь узнаёт
  "лицензия активна", но не может её обойти (реальное исполнение всё равно
  требует модуля)

## 5. Сборка модуля

- Форк `mta-sdk-module`, добавляются папки:
  `source/sdk/license/`, `source/sdk/license/crypto/`, `source/sdk/license/hwid/`
- Сборка: `cmake --preset win-mingw && cmake --build` (.dll)
  и `linux-gcc` (.so) — оба артефакта публикуются на площадке.
- Публичный ключ Ed25519 (License Server) зашивается при сборке —
  продакшен-сборка и dev-сборка используют разные ключи (dev: тестовый).

## 6. Модель угроз (что защищаем и от чего)

| Угроза | Защита |
|---|---|
| Покупатель просто копирует файл скрипта | Бесполезно: blob без DEK не расшифровать |
| Покупатель переносит на другой сервер | HWID-биндинг: DEK привязан к железу |
| Покупатель пытается подделать `license_check()` | Реальное исполнение — в C++; Lua-функция не расшифровывает |
| Подмена DNS / фейковый License Server | Модуль требует подпись Ed25519 (ключ зашит в .dll) |
| Replay старого "active" ответа | nonce + timestamp TTL ±30 сек |
| Дешифровка перехваченного traffic | TLS + подпись Ed25519 поверх payload (не только транспорт) |
| Слив скрипта через модуль-парсер | Watermark в каждой копии: узнаём источник |
| Неуязвимость при остановке сервера | Grace 48ч, потом модуль сам отключает скрипт |

## 7. Что DRM НЕ защищает (важно понимать)

- **Модели (DFF/TXD)** — движок читает их открыто; защита = водяной знак + поиск утечек.
- **Память MTA-сервера** — расшифрованный скрипт рано или поздно оказывается
  в памяти. DRM = "cost-raising", не абсолютная защита.
- **Обход реверс-инженерией** — C++ усложняет, но не исключает. Компенсируется
  водяными знаками и мгновенным отзывом утечки.
