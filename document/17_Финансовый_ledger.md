# 💰 Финансовый Ledger

> Создан по итогам аудита: `purchase != payment != settlement != payout`,
  а старая схема смешивала их в одной таблице. Двойная запись — основа
  честной системы с деньгами.

---

## 1. Принцип: immutable append-only

Каждое движение денег — отдельная запись в `financial_transactions`.
Записи **никогда** не редактируются и не удаляются. Ошиблась запись —
создаём компенсирующую (storno).

## 2. Типы транзакций

```
payment_received   — деньги пришли от покупателя (через провайдера)
platform_fee       — комиссия площадки (15%)
provider_fee       — комиссия провайдера (ЮKassa)
seller_pending     — зарезервировано продавцу (escrow hold)
seller_paid         — выплачено продавцу (после подтверждения)
refund             — возврат покупателю
chargeback        — возврат принудительный (спор с банком)
adjustment         — ручная корректировка (с reason в audit_log!)
```

## 3. Пример потока (покупка 2500 ₽, комиссия 15%)

| tx_type | amount_cents | balance_after (продавца) | комментарий |
|---|---|---|---|
| payment_received | 250 000 | 0 | +2500 ₽ через ЮKassa |
| provider_fee | -29 000 | 0 | fee провайдера (условно) |
| platform_fee | -37 500 | 0 | 15% — площадке |
| seller_pending | 183 500 | 0 | escrow hold |
| *(покупатель подтвердил)* | | | |
| seller_paid | 183 500 | 183 500 | payout продавцу |

⚠️ Цифры условные — фактический `provider_fee` берётся из
актуального прайса ЮKassa на момент подключения (условия менялись
в 2026, комиссия площадки «15%» не окончательная до сверки).

## 4. Правила

1. **Сверка с провайдером (reconciliation):** ежедневно сверять
   выплаты в БД с отчётом ЮKassa. Расхождение — P1-инцидент.
2. **Reconciliation report:** `SELECT` суммы по дням vs API ЮKassa.
3. `balance_after` пересчитывается и проверяется инвариантом
   (Σ transactions == balance продавца).
4. Chargeback/refund не проходят, если уже есть seller_paid — только
   через dispute → adjustment.
5. Все транзакции пишутся в `audit_log` с actor_id.

## 5. Escrow-стейт-машина (БД) × Safe Deal (провайдер)

```
БД:         in_escrow → released | refunded
Провайдер:  холд → выплата | возврат

Правило: переход в БД возможен только ПОСЛЕ подтверждения
от провайдера. Никаких "optimistic" переходов.
```
