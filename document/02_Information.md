## 1. Что выбирали и почему: языки программирования

| Что выбираем | Выбор | Почему | Альтернативы |
|---|---|---|---|
| Основной язык (Backend) | **TypeScript** (Node.js) | Быстрый старт, один язык с frontend, полно библиотек | Python, Go |
| Frontend | **React + TypeScript** | Стандарт индустрии | Vue, Svelte |
| Стили | **Tailwind CSS** | Скорость разработки, готовые компоненты | Bootstrap |
| База данных | **PostgreSQL** | Надёжность, сложные запросы (продажи, лицензии) | MySQL, MongoDB |
| Кэш/очереди | **Redis** | Хранение сессий, фоновые задачи | RabbitMQ |
| DRM-модуль (для MTA-серверов) | **C++** (20) | Lua — основной язык ресурсов MTA; C++ — слой нативных модулей-расширений сервера (через него реализуется DRM). SDK (`mta-sdk-module`) уже есть | альтернатив для модулей нет |
| Криптография | **Ed25519 + AES-256-GCM** (libsodium) | Современные стандарты, не «самодельные шифры» | RSA+AES |

**Вывод:** Backend и Frontend разговаривают на одном языке (TypeScript),
что упрощает поддержку силами одного человека. DRM-модуль — отдельная
история на C++, она подключается через API площадки.

## 3. Как связаны системы (взаимодействия)

| Взаимодействие | Как работает |
|---|---|
| Frontend → Backend | REST API (JSON) через HTTPS |
| Backend → БД | Прямое подключение (SQL) |
| DRM-модуль → License Server | REST API через HTTPS (heartbeat) |
| Платежи (ЮKassa) → Backend | Webhook (уведомления о статусе оплаты) |
| Чаты/уведомления | WebSocket (двусторонняя связь в реальном времени) |
| Email-уведомления | Через SMTP-провайдера (Resend/Mailgun) |
| Хранение файлов (скрипты, картинки) | S3-хранилище (MinIO, self-hosted) |

## 4. Роли систем (кто за что отвечает)

- **Frontend** — «лицо» площадки. Всё, что видит покупатель/продавец в браузере.
- **Backend** — «мозг». Обрабатывает платежи, выдаёт лицензии, следит
  за подписками, считает комиссию, хранит все данные.
- **License Server** (часть Backend) — «охранник». С ним разговаривает
  только DRM-модуль. Может жить на отдельном сервере, чтобы пережить
  падение основной площадки.
- **DRM-модуль (C++)** — «агент» на сервере покупателя. Расшифровывает
  скрипты, следит за актуальностью лицензии, отключает продукт при отзыве.

## 5. Почему такой стек подходит для одного человека

1. **TypeScript везде** — не надо «переключать мозг» между языками.
2. **Все системы стандартные** — много документации, легко найти ответ.
3. **AI-агенты (Claude, Cursor) отлично помогают именно с этим стеком** —
   вас не будут блокировать ошибки синтаксиса.
4. **PostgreSQL + Redis** — «скучные» технологии, которые не ломаются.
5. **C++ только для DRM-модуля** — и для него уже готов SDK
  (`mta-sdk-module`), осталось «просто» написать логику лицензирования.
