# 🧪 Тестирование — что и как проверяем

> Стратегия: тестировать критичное для денег и лицензий — обязательно.
> Остальное — быстрые ручные проверки по чек-листам.

---

## 1. Пирамида тестирования (что тестируем автоматом)

| Уровень | Что | Покрытие | Инструменты |
|---|---|---|---|
| Unit | чистая логика (крипто, расчёт комиссии, HWID-хэш) | высокая | Vitest / Jest |
| Integration | API-эндпоинты + БД | средняя | Supertest + testcontainers |
| E2E | сценарии через браузер | критичные пути | Playwright |
| Smoke на prod | "сайт жив?" после deploy | каждые 5 мин | uptime-пинг |

## 2. Обязательно тестируем автоматом (деньги и лицензии)

```
1. Регистрация → покупка → выдача лицензии
2. Heartbeat: активная, отозванная, истекшая лицензия
3. HWID: привязка, замена, превышение лимита
4. Escrow: подтверждение, автоподтверждение по TTL, спор
5. Webhook ЮKassa: success, cancel, повторная отправка (idempotency)
6. Комиссия: правильный расчёт 15%
7. DRM: правильность расшифровки + отказ при неверном ключе
```

## 3. Чек-лист перед релизом (ручной, 15 минут)

```
□ Регистрация нового пользователя работает
□ Каталог открывается, картинки грузятся
□ Тестовая покупка проходит (test_ режим ЮKassa)
□ Тестовая лицензия выдаётся, HWID привязывается
□ Escrow-поток: покупка → подтвердить → продавец получил статус
□ Отзыв лицензии из админки моментально отключает скрипт
□ Email-уведомление о покупке приходит
□ На мобильном ничего не разваливается (адаптив)
□ Speed: главная < 2 сек (Lighthouse mobile)
```

## 4. Тестовые данные

- Отдельный тестовый магазин в ЮKassa (ключи `test_*`).
- Сид-скрипт `npm run seed` — создаёт тестовых пользователей,
  товары и лицензии для локальной разработки.
- **Никогда** не запускать тесты против продакшен-БД.

## 5. Canary-деплой (когда будет много пользователей)

1. Deploy на прод → 5 минут smoke-тестов вручную.
2. Ошибка → мгновенный rollback (`git tag previous` + повторный deploy).
3. Смотреть `pm2 logs` первые 10 минут после деплоя — обязательно.

## 6. Bug tracking

- Каждый баг → issue в репозитории → приоритет P1 (деньги) / P2 (функции) / P3 (косметика).
- Перед закрытием: шаги воспроизведения + как исправлено + почему не повторится.

## 7. Invariant tests (добавлено по итогам аудита) ⭐

Для marketplace с деньгами invariant-тесты ценнее процента coverage:

### Money invariant
```
payment = seller_amount + platform_fee + provider_fee
```

### License invariant
```
revoked license → НЕ МОЖЕТ иметь active installation
(проверять каскадным запросом в CI)
```

### Purchase invariant
```
successful payment → exactly one purchase → exactly one license
(дубликаты вебхуков не создают дублей)
```

### Webhook invariant
```
10 идентичных webhooks → ровно один финансовый эффект
```

### Refund invariant
```
refund не может превысить captured amount
```

### Ledger invariant
```
Σ financial_transactions по seller == текущий баланс seller
(пересчитывать каждую ночь)
```
